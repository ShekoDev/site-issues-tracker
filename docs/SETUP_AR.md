# Site Tracker — واجهة النظام (Vite + React + Supabase)

واجهة **مشروع تجريبي** لإدارة ومتابعة بنود الموقع الـ80.
مبنية على حزمة الباك إند الموجودة في مجلد `ITEM-backend` — نفس الجداول والعروض والدوال بلا أي تغيير في السكيما.

---

## 1) المتطلبات

| | |
|---|---|
| Node.js | الإصدار 18 أو أحدث — <https://nodejs.org> |
| حساب Supabase | مجاني — <https://supabase.com> |

للتأكد أن Node مثبّت، افتح موجّه الأوامر واكتب:

```bash
node -v
```

## 2) إنشاء مشروع Supabase وتشغيل ملفات SQL

1. ادخل <https://supabase.com/dashboard> ← **New project** ← اختر اسمًا وكلمة مرور لقاعدة البيانات، والمنطقة الأقرب (Frankfurt أو Bahrain).
2. بعد ما يجهز المشروع، افتح **SQL Editor ▸ New query**.
3. الصق محتوى كل ملف واضغط **Run**، **بهذا الترتيب بالضبط**:

```
01_schema.sql  →  02_rls.sql  →  03_seed.sql  →  04_storage.sql  →  06_activity_log.sql
```

ثم ملف التحقق **`98_verify_install.sql`** — يرجّع 16 فحصًا، كلهم لازم يقولوا «✅ سليم».

> `99_reset_progress.sql` أداة منفصلة لتصفير الإنجاز — تُشغَّل وقت الحاجة فقط، وليست جزءًا من التركيب.

4. للتأكد أن كل شيء ركّب صح، شغّل:

```sql
select count(*) from public.profiles;        -- المتوقع: 11
select count(*) from public.tasks;           -- المتوقع: 80
select count(*) from public.execution_steps; -- المتوقع: 320
```

## 3) حساب الأدمن — الحساب الوحيد الذي يُنشأ يدويًا

باقي المستخدمين يُضافون **من داخل الموقع نفسه** من صفحة «المستخدمون».

**أولًا** شغّل في SQL Editor ملف **`10_admin_account.sql`** — يحوّل حساب الأدمن إلى `sheko@tracker.local`.

**ثانيًا** من **Authentication ▸ Users ▸ Add user ▸ Create new user**:

| الحقل | القيمة |
|---|---|
| Email | `sheko@tracker.local` |
| Password | كلمة مرور قوية من اختيارك |
| Auto Confirm User | ✅ **لازم تتفعّل** — بدونها الحساب لا يستطيع الدخول |

الربط بالملف الشخصي تلقائي عن طريق البريد (مُشغّل `trg_link_auth_user`).

## 3-ب) نشر دالة إدارة المستخدمين (Edge Function)

إنشاء حساب دخول يحتاج مفتاح `service_role` الذي يتجاوز كل سياسات RLS، ولا يجوز أن يصل للمتصفح إطلاقًا.
لذلك يعيش على الخادم في Edge Function تتحقق أولًا أن المُنادي أدمن فعلًا.

من لوحة Supabase ▸ **Edge Functions** ▸ **Deploy a new function** ▸ **Via Editor**:

1. الاسم: **`admin-users`** — بالحرف، الواجهة تناديه بهذا الاسم
2. امسح الكود الافتراضي والصق محتوى الملف `supabase/functions/admin-users/index.ts`
3. **Deploy**

لا تحتاج ضبط أي متغيّرات — `SUPABASE_URL` و `SUPABASE_SERVICE_ROLE_KEY` تُحقن تلقائيًا في Edge Functions.

> بديل لمن يفضّل سطر الأوامر: `npx supabase functions deploy admin-users`

### ماذا تتيح لك بعد النشر

من صفحة **المستخدمون** في الموقع (للأدمن فقط):

| الزر | ماذا يفعل |
|---|---|
| **+ مستخدم جديد** | يضيف الملف الشخصي وينشئ حساب الدخول في خطوة واحدة — البريد يتولّد تلقائيًا `<اسم الدخول>@tracker.local` |
| **إنشاء حساب** | لملف شخصي موجود بلا حساب دخول (الـ10 مستخدمين القادمين من ملف الوورد) |
| **كلمة المرور** | تعيين كلمة مرور جديدة لأي مستخدم |
| **تعديل** | الدور والمسمى الوظيفي والتفعيل |
| **تعطيل** | يحذف حساب الدخول فقط — **البنود وسجل التغييرات تبقى كما هي** |

المستخدمون العشرة الباقون (عمر قاسم، فهمي، عبد الرحمن، …) ملفاتهم الشخصية موجودة بالفعل من `03_seed.sql`،
فيظهرون في الجدول بحالة «لم يُنشأ حساب دخول» وأمام كل واحد زر **إنشاء حساب**.

## 4) ربط الواجهة بقاعدة البيانات

من **Project Settings ▸ API** انسخ `Project URL` و `anon public key`، ثم أنشئ ملفًا اسمه **`.env.local`** في هذا المجلد:

```
VITE_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
```

> مفتاح `anon` آمن في المتصفح لأن كل الصلاحيات مفروضة بسياسات RLS داخل القاعدة.
> **لا تضع مفتاح `service_role` هنا إطلاقًا** — يتجاوز كل السياسات.

## 5) التشغيل

```bash
npm install     # مرة واحدة فقط
npm run dev     # يفتح http://localhost:5173
```

للنسخة النهائية:

```bash
npm run build   # ينتج مجلد dist
npm run preview # لمعاينة النسخة النهائية محليًا
```

للنشر على الإنترنت: ارفع مجلد `dist` على Netlify أو Vercel أو Cloudflare Pages،
وأضف نفس متغيّري `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY` في إعدادات المنصة.

ملفات إعداد النشر جاهزة في المشروع: `public/_redirects` و `netlify.toml` و `vercel.json` —
وظيفتها توجيه كل المسارات إلى `index.html` حتى لا تعطي الروابط الداخلية 404 بعد الرفع.

## 7) ملاحظات تقنية

- **الصلاحيات مفروضة في القاعدة بـRLS**، والواجهة تخفي الأزرار فقط لتحسين التجربة. لو حاول مستخدم تعديل ما لا يملكه، القاعدة ترفض والواجهة تعرض رسالة الرفض العربية كما هي.
- **`record_login` يُستدعى تلقائيًا** بعد كل دخول ناجح، و`record_logout` قبل الخروج — بدونهما يفضل `login_count` صفر وتظهر حالة الحضور «حساب موجود ولم يدخل بعد».
- **نسبة الإنجاز تُحسب في القاعدة** من الخطوات المنجزة (`recalc_task`)، والواجهة لا تحسبها ولا تكتبها.
- **نقل البند** يمرّ عبر الدالة `transfer_task` والسبب إلزامي (٣ أحرف على الأقل) — لا يوجد تعديل مباشر على `assigned_to`.
- **المرفقات** ترفع إلى bucket `task-attachments` بمسار `<رقم البند>/<uuid>-<اسم الملف>` لأن سياسة الصلاحية مبنية على أول جزء من المسار. الحد 20 ميجابايت.
- **التقارير PDF** تُنتَج بالطباعة من المتصفح (Ctrl+P ← Save as PDF) بدل مكتبة PDF — يحافظ على العربية RTL وتشكيل الحروف بلا مشاكل.
- **التحديث اللحظي** مفعّل على `tasks` و`execution_steps` عبر Supabase Realtime.
